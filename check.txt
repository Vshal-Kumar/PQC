1. Secrecy & Confidentiality Properties
Session Key Secrecy: Proves that an active network attacker cannot learn the derived symmetric encryption session key.
Client Data Secrecy: Proves that the payloads sent by the client over the established session remain completely confidential.
Server Data Secrecy: Proves that payloads sent by the server to an honest client cannot be decrypted by an attacker.
Perfect Forward Secrecy (PFS): Proves that even if the long-term signature keys (c_dsa_sk and s_dsa_sk) are compromised in a subsequent phase, the secrecy of past session keys and payloads remains intact.
2. Authentication & Integrity Properties
Client Authentication: Proves that the server only accepts a session if the genuine client initiated it.
Server Authentication: Proves that the client only completes the handshake if the genuine server initiated the response.
Mutual Authentication: Proves that both parties achieve a matching agreement on each other's identities.
Replay Resistance: Proves that an attacker cannot capture old handshake messages and replay them to establish a duplicate session (verified via injective correspondence queries).
Key Confirmation: Proves that both parties agree on the exact same derived symmetric session key at the end of the handshake.
Transcript Binding: Proves that both parties agree on the exact sequence of exchanged handshake messages (nonces, session IDs, and keys).
Identity Binding: Proves that the derived session keys are mathematically bound to the verified identities of the participants.
Message Integrity: Proves that an attacker cannot alter symmetric channel messages without causing decryption failure.
Ciphertext Integrity (AEAD): Proves that the AEAD symmetric wrapper correctly protects ciphertext payloads from unauthorized tampering.
3. Handshake & Session Binding Protections
KEM Ciphertext Substitution Resistance: Proves that an attacker cannot swap the KEM ciphertext (kem_ct) in transit to manipulate key derivation without causing the signature verification to fail.
Unknown Key-Share (UKS) Resistance: Proves that an attacker cannot trick a client into establishing a session where the client believes it is talking to the server, but the server believes it is talking to a third party.
Reflection Attack Resistance: Proves that an attacker cannot reflect the client's own handshake packets back to it to complete a connection.
Parallel Session Security: Proves that multiple concurrent sessions run independently and do not leak or mix up keys.
Session Mix-Up Resistance: Proves that session parameters (such as nonces and session IDs) prevent cross-session interference.
Nonce Freshness: Proves that new nonces are generated independently for each handshake session.
Session ID Uniqueness: Proves that session IDs generated by the server are unique per handshake session.
